Indicator dictionary

coverage_rate
Share of personnel in a ready state out of total active personnel. Answers: can the available team cover planned assignments?
expiring_quals_30d
Count of qualifications lapsing within 30 days. Prompts renewal before an assignment is blocked.
equipment_available
Assets in service and not awaiting maintenance, over total assets.
overdue_work_orders
Open work orders past their due date. Each links to the specific asset and site.

Each indicator ships with its definition, source field, and update frequency so numbers mean the same thing across organizations.

Data model & dictionary

adapt the fields, keep the definitions
personnel
  person_id        text     unique identifier (stable across records)
  name             text
  role             text     maps to a role's required qualifications
  site             text
  availability     enum     available | on_leave | off_shift | unavailable
  qualifications[] record   { code, obtained, expires }   e.g. CPR, GuardCard, CDL, OSHA10
  # readiness_state is DERIVED, never entered by hand:
  #   blocked  = unavailable OR any required qualification lapsed
  #   review   = a required qualification expires within 30 days, or a record is incomplete
  #   ready    = available AND all required qualifications current

equipment
  asset_id         text     unique identifier
  tag              text     field/asset tag (naming convention enforced)
  site             text
  status           enum     in_service | maintenance | out_of_service
  work_orders[]    record   { wo_id, description, due, closed }

# Validation rules (see checklist): unique IDs, required fields present,
# controlled vocabularies for enums, no expiry in the past without a flag,
# every work order resolves to an existing asset.

This is the "asset/work-order data structure" and "data dictionary" named in the proposed endeavor — published openly so any organization can examine and adapt it without commissioning a new system.
